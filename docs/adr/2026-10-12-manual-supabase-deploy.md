# ADR: Supabase の本番反映を手動実行のワークフローにする

## 背景と課題

DB マイグレーションと Edge Function の反映は手元の `npx supabase db push` / `npm run online:deploy` で行っていた。手順の順番（マイグレーション → Edge Function → アプリ）を間違えやすく、実行記録も残らない。

## 選択肢

1. 手元で手動実行を続ける。
2. main へのマージで自動反映する。アプリは TestFlight で手動配布のため、サーバーだけ先に変わる時点がマージに引きずられる。本番 DB の変更は戻しにくい。
3. GitHub Actions の手動実行（workflow_dispatch）で、決まった順に反映する。

## 決定と理由

3を採用する。順番を固定し、ログを GitHub に残す。`dry_run` を既定にして、適用待ちのマイグレーションを確認してから反映する。Secrets は `production` 環境に置き、必要なら実行前の承認を必須にできる。

## 利点と欠点

- 利点: 順番の誤りがなくなる。手元に Supabase の認証情報を置かなくてよい。
- 欠点: Supabase のアクセストークンと DB パスワードを GitHub に預ける。CLI は `latest` を使うため、CLI の変更で動作が変わり得る。

## 見直し条件

反映の頻度が上がった場合や、ステージング環境を作った場合は、ステージングへの自動反映を検討する。
