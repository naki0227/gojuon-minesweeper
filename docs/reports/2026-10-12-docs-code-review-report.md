## コードレビュー結果

静的読解で確認した。以下の競合・失敗シナリオはSupabase実環境での再現テストをまだ行っていないため、修正前に失敗注入または同時実行テストで固定する。

1. **P1: 古い締切で新しい手番を敗北扱いし得る。** `supabase/functions/online-game/index.ts:448-469` は部屋を読み込んだ時点の締切を判定し、その後に非公開状態を読み込む。間に相手の操作が確定して同じ手番の別フェーズへ進むと、更新後の非公開状態に対し、更新前の締切を理由に `concedeGame` できる。`commitGame` は新しい非公開バージョンをそのまま採用するため拒否されない。締切・手番・バージョンを単一の原子的な更新条件に入れ、境界時刻の競合テストを追加する。
2. **P1: 公開状態と非公開状態が片方だけ更新され得る。** 同ファイル `139-179` の `commitGame` は非公開行を更新した後で公開行を更新する。後者が失敗すると、次の操作は新しい非公開状態に進む一方、両端末には古い盤面と締切が残る。`193-218` の開始処理も分割更新で、`223-241` は開始前に部屋を `playing` にする。後続失敗時は `app/online.tsx:247-253` の「対戦を準備しています…」から進めなくなる。DB関数などで両行を同一トランザクションに入れ、途中失敗のテストを作る。
3. **P2: 同時の再戦希望が失われる。** `supabase/functions/online-game/index.ts:472-501` は各端末が読んだ2つの再戦フラグを丸ごと上書きするが、この更新では `version` を増やさない。同じ版を読んだ2人が同時に押すと最後の書き込みだけが残り、どちらも「相手を待っています」となり得る。フラグ更新と再戦開始を原子的にし、同時リクエストをテストする。
4. **P2: Web公開が品質ゲートと独立して走る。** `.github/workflows/deploy-web.yml:4-54` はmainへのpushでCIと並走し、整形・lint・単体テストを実行せずに公開する。`.github/workflows/ci.yml:25-41` の失敗を待たないため、CIが赤いコミットでもWebは公開可能。CI成功をデプロイの前提にし、デプロイ側も `npm ci` に統一する。
5. **P2: クライアントとサーバーのゲームルールがずれる運用余地。** `package.json` の `online:deploy` は手動であり、`.github/workflows/deploy-web.yml` と `.github/workflows/testflight.yml` にEdge Functionの同期・デプロイ確認はない。`src/online/rules.ts:126-129` は保存された問題IDを現行バンクから復元するため、データ差し替え時には進行中の部屋も影響する。配布前にサーバー版を確認する手順または自動ゲートを作る。
6. **P2: サーバー本体がCIの型チェック・lintから外れている。** `tsconfig.json:16` と `eslint.config.js` は `supabase/` を除外し、`.github/workflows/ci.yml` にDeno検証がない。上記の対戦サーバー約595行が通常の品質ゲートを通らない。Edge Function専用のDeno型チェックと失敗・競合テストをCIへ追加する。
7. **P3: 通信失敗と古い応答の扱いが弱い。** `src/online/client.ts:83-90` は取得エラーを見ずにnullとして返し、`src/online/useOnlineRoom.ts:80-82` の定期更新は失敗を利用者へ伝えない。同hook `30-40,151-154` は退出後の古い非同期応答を拒否しないため、退出済みの部屋が画面に戻る可能性がある。エラー表示と要求世代番号・キャンセルを導入する。
8. **P3: 問題バンクの読み込み・集計コストは計測対象。** 13個・合計約3MBのJSONを `src/data/questions.ts:25-95` で起動時にすべて組み立て、`src/components/HomeSetup.tsx:243-259` ではグループごとに全問題を走査する。現時点で実機の遅延を測っていないため障害とは断定しない。端末の起動・設定画面描画時間を計測し、必要なら集計の事前計算や索引化を検討する。
9. **P3: UIとサーバーファイルが大きい。** `src/components/HomeSetup.tsx` は814行、`app/online.tsx` は657行、`app/index.tsx` は584行、Edge Functionは595行。表示、状態、通信の変更が同一ファイルに集中しやすい。上記の不具合修正と混ぜず、責務ごとの小さな分割を別作業で進める。
